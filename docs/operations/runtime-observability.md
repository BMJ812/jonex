# Runtime observability

## Scope

JØNEX records application lifecycle, plugin discovery, telemetry sampling,
frontend bootstrap, unhandled browser errors, promise rejections, and React
render failures.

## Log locations

The official Tauri log directory is used.

| Platform | Location |
| --- | --- |
| Windows | `%LOCALAPPDATA%\io.jonex.platform\logs` |
| Linux | `$XDG_DATA_HOME/io.jonex.platform/logs` or `$HOME/.local/share/io.jonex.platform/logs` |
| macOS | `$HOME/Library/Logs/io.jonex.platform` |

The exact filename is generated by the Tauri logging plugin.

## Retention policy

- Maximum file size: 5 MB
- Rotated files retained: 5
- Debug builds: JØNEX crate debug records enabled
- Release builds: informational records and above

## Frontend containment

The root React tree is wrapped in `RuntimeErrorBoundary`.

When a rendering error reaches the boundary:

1. The failure is normalized into a runtime incident.
2. A local incident identifier is generated.
3. Error and component-stack details are written to the local log.
4. The shell displays retry and reload controls.
5. Raw stack traces are not displayed in the normal interface.

## Global failures

The frontend logger records:

- `window.error` events
- Unhandled promise rejections
- Root-element bootstrap failures

## Data handling

Logs are local-only. Do not add automatic log upload, external crash
reporting, or third-party analytics without a separate architecture decision,
privacy review, UI disclosure, and explicit user consent.

## Operator procedure

When reporting a runtime failure, collect:

- Incident identifier displayed by JØNEX
- Application version
- Operating-system version
- Reproduction steps
- Relevant local log excerpt with secrets removed

Do not publish complete logs without reviewing them for hostnames, paths,
service names, addresses, credentials, tokens, or personal data.
